\subsection{FPGA Verification: Zynq On-Board Readback}
\label{sec:verify:fpga}

The FPGA bitstream is verified end-to-end with hardware in the loop. After loading the PL configuration, the PS-side Python program initialises the NPU (\texttt{o1.download()}), asserts the start pulse (\texttt{pulse\_start()}), polls the done flag (\texttt{wait\_done(20.0, 0.001)}), and reads back the embedding vector word by word over the 128-bit AXI-GPIO readout bus by iterating addresses \texttt{0x40000}--\texttt{0x40007} and calling \texttt{request\_read(addr)} followed by \texttt{read\_128bit\_data()}. A representative inference completes in \emph{0.128619\,s} of wall-clock time, consistent with the 127.8\,ms cycle-budget estimate from Section~\ref{sec:hw:backend:fpga} after PS round-trip overhead. The 128 8-bit embedding values read back from addresses \texttt{0x40000}--\texttt{0x40007} are compared byte by byte against the C-model reference written to disk by the same hex-generation script that drives the ASIC simulation testbench.

Figure~\ref{fig:fpga_readback} shows the reference embedding (left, from the C-model) alongside the PS readout from a real Zynq run (right). The two streams match bit-for-bit on every address.

The on-board test exercises the full data path that the simulator alone cannot: the AXI Interconnect, the BRAM-mapped WGT / A/O / Param RAMs, the PS-PL handshake on \texttt{start}/\texttt{done}, and the readout bus. Together with the ASIC three-tier signoff in Section~\ref{sec:verify:asic}, this closes the loop on functional verification of the shared RTL.
