\section{Introduction}
\label{sec:intro}

\paragraph{Goal.} This project implements a fixed-point, MobileFaceNet-specific convolution frontend accelerator. The accelerator runs the full 50-layer MobileFaceNet inference flow autonomously, from the first $3\times3$ convolution through to the final $7\times6$ global depthwise convolution and $1\times1$ linear projection, producing a 128-dimensional face embedding with no host intervention between layers.

\paragraph{Approach overview.} Rather than building a fully configurable NPU, the design is \emph{specialized} to MobileFaceNet: INT16 Q10 weights/activations, hard-wired support for the five operator types used in MobileFaceNet ($3\times3$ conv, $3\times3$ depthwise, $1\times1$ pointwise, $7\times6$ global depthwise, residual add), and a 50-entry on-chip ROM that describes the per-layer configuration in 64-bit words. The same baseline RTL is implemented along two independent paths: an ASIC flow in FreePDK45 (12$\times$12 systolic array) and an FPGA flow on Zynq, allowing direct comparison of physical metrics, verification effort, and design productivity between the two technologies.

\paragraph{Prior art.} The MobileFaceNet topology itself is taken from Chen et al.~\cite{chen2018mobilefacenetsefficientcnnsaccurate}, with the non-square $112\times96$ input variant from Sun et al.~\cite{Linjun_SUN20202019EDL8103}. Our dataflow design draws on Eyeriss~\cite{7738524} (output-stationary mapping, sliding-window reuse) but specializes the control path to the fixed MobileFaceNet layer sequence. Recent edge-deployment alternatives such as EdgeFace~\cite{george2024edgefaceefficientfacerecognition} target the same use case at the model level; our work targets the hardware level for an existing trained network.
