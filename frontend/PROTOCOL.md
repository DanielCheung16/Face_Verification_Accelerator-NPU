# Frontend Device Protocol

This document defines the current system-level protocol between the layer
devices, the layer switcher, the shared postprocess block, and the shared
write-back path.

The goal is to make each layer device replaceable. A new layer device should
use the same API as `conv1x1_level3_top`.

## Common Parameters

| Name | Meaning |
| --- | --- |
| `ROW` | Tile size in the M direction. |
| `COL` | Number of output channels packed in one tile row. |
| `DATA_W` | Activation and weight data width. Currently 8 bits. |
| `ACC_W` | Accumulator width. Currently 32 bits. |
| `OUT_W` | Postprocess output width. Currently 8 bits. |
| `GB_DATA_W` | Global-buffer word width. |

Current Level3 write-back assumes:

```text
GB_DATA_W = COL * OUT_W
```

Therefore, when `COL=16`, one output row is 128 bits. When `COL=4`, one output
row is 32 bits.

## Device to Switcher Interface

Each layer device connects to the switcher through three groups of signals:
control/config, activation-output SRAM access, and weight SRAM access.

### Control

| Signal | Direction | Meaning |
| --- | --- | --- |
| `start_i` | switcher to device | One-cycle pulse to start one scheduled layer. |
| `busy_o` | device to switcher | High while the device owns the layer. |
| `done_o` | device to switcher | High when the current scheduled layer is complete. |
| `run_en_i` | system to device | Global run enable. Normally tied high in the current system. |

Handshake rules:

1. The switcher asserts `start_i` for one cycle.
2. The device raises `busy_o` after accepting the layer.
3. The switcher accepts `done_o` only after it has observed `busy_o`.
4. `done_o` means the whole scheduled layer is finished, not one tile.
5. A layer device should not issue SRAM requests after `done_o` is accepted.

### Layer Configuration

| Signal | Meaning |
| --- | --- |
| `layer_idx_i` | Program/layer index from the layer schedule. |
| `k_size_i` | Reduction dimension size. |
| `m_size_i` | Output matrix rows, normally `H * W`. |
| `n_size_i` | Output channels. |
| `act_base_addr_i` | Base address of the input activation in A/O SRAM. |
| `wgt_base_addr_i` | Base address of the weight in Weight SRAM. |
| `out_base_addr_i` | Base address of the output in A/O SRAM. |
| `residual_en_i` | Enables residual read path for residual layers. |
| `residual_base_addr_i` | Base address of residual input in A/O SRAM. |

Postprocess configuration is also delivered with the layer configuration:

| Signal | Meaning |
| --- | --- |
| `mode_i` | Postprocess mode, such as requant, residual, or PReLU. |
| `bias_i[COL]` | Folded bias per output channel. |
| `multiplier_i[COL]` | Requant multiplier per output channel. |
| `shift_i[COL]` | Requant shift. |
| `zero_point_i[COL]` | Output activation zero-point. |
| `prelu_multiplier_i[COL]` | PReLU multiplier per output channel. |
| `prelu_shift_i[COL]` | PReLU shift. |
| `residual_multiplier_i[COL]` | Residual path multiplier. |
| `residual_shift_i[COL]` | Residual path shift. |
| `residual_zero_point_i[COL]` | Residual input zero-point correction. |

The switcher currently broadcasts one active layer configuration at a time.
Only the decoded active device should consume it.

### Activation/Output SRAM Read

| Signal | Direction | Meaning |
| --- | --- | --- |
| `gb_act_rd_valid_o` | device to switcher | Read request valid. |
| `gb_act_rd_addr_o` | device to switcher | A/O SRAM read address. |
| `gb_act_rd_data_i` | switcher to device | Returned A/O SRAM read data. |

Rules:

1. There is no ready signal in the current SRAM protocol.
2. The device must schedule around the SRAM read latency.
3. This read port is used for activation preload and residual read.

### Weight SRAM Read

| Signal | Direction | Meaning |
| --- | --- | --- |
| `gb_wgt_rd_valid_o` | device to switcher | Weight read request valid. |
| `gb_wgt_rd_addr_o` | device to switcher | Weight SRAM read address. |
| `gb_wgt_rd_data_i` | switcher to device | Returned weight SRAM read data. |

Rules are the same as the A/O read port: no backpressure, and the device must
handle read latency internally. (refering to `synchronized reading`)

### A/O SRAM Write

Layer devices do not directly generate final A/O writes in the current shared
postprocess design. Writes are generated by the shared write-back path:

```text
device raw tile -> postprocess -> wb_buffer -> wr_controller -> switcher -> A/O SRAM
```

The switcher still sees the write as a device-owned write channel:

| Signal | Direction | Meaning |
| --- | --- | --- |
| `dev_ao_wr_valid_i` | write-back path to switcher | A/O write valid. |
| `dev_ao_wr_addr_i` | write-back path to switcher | A/O write address. |
| `dev_ao_wr_data_i` | write-back path to switcher | Packed output word. |
| `dev_ao_wr_mask_i` | write-back path to switcher | Byte-lane write mask. |

## Device to Shared Postprocess Interface

A layer device outputs one raw tile to the shared postprocess block.

| Signal | Direction | Meaning |
| --- | --- | --- |
| `post_valid_tile_o` | device to postprocess | One-cycle pulse indicating a raw tile is available. |
| `post_valid_tile_i` | postprocess to device | One-cycle pulse indicating the processed tile is valid. |
| `post_row_base_o` | device to postprocess | Global M-row base of this tile. |
| `post_col_base_o` | device to postprocess | Global N-channel base of this tile. |
| `post_m_size_o` | device to postprocess | Full output M size. |
| `post_n_size_o` | device to postprocess | Full output N size. |
| `post_mode_o` | device to postprocess | Postprocess mode for this tile. |
| `post_valid_o[ROW][COL]` | device to postprocess | Raw lane valid matrix. |
| `post_acc_o[ROW][COL]` | device to postprocess | 32-bit accumulator tile. |
| `post_residual_o[ROW][COL]` | device to postprocess | Residual tile, when used. |

The device also forwards the per-channel postprocess parameters:

```text
post_bias_o[COL]
post_multiplier_o[COL]
post_shift_o[COL]
post_zero_point_o[COL]
post_prelu_multiplier_o[COL]
post_prelu_shift_o[COL]
post_residual_multiplier_o[COL]
post_residual_shift_o[COL]
post_residual_zero_point_o[COL]
```

Handshake rules:

1. The device asserts `post_valid_tile_o` for one cycle after the raw tile is ready.
2. The raw tile data and metadata must be stable on that cycle.
3. The postprocess block returns `post_valid_tile_i` when `data_o[ROW][COL]` is valid.
4. The device must not start write-back capture until `post_valid_tile_i` is high.

## Device to Write-Back Path Interface

The device controls when the processed tile should be captured and where it
should be written.

| Signal | Direction | Meaning |
| --- | --- | --- |
| `wb_capture_en_o` | device to `wb_buffer` | One-cycle pulse to capture postprocess output tile. |
| `wb_done_i` | `wr_controller` to device | Write-back for the current tile is complete. |
| `wb_m_size_o` | device to `wr_controller` | Full output M size. |
| `wb_n_size_o` | device to `wr_controller` | Full output N size. |
| `wb_out_base_addr_o` | device to `wr_controller` | Output base address in A/O SRAM. |

Write-back rules:

1. `wb_capture_en_o` is asserted after `post_valid_tile_i`.
2. `wb_buffer` captures the full `ROW x COL` processed int8 tile.
3. `wr_controller` reads one tile row per cycle from `wb_buffer`.
4. Each `wb_buffer` row is packed into one global-buffer word.
5. `wr_controller` walks M tiles first, then moves to the next N tile.
6. `wb_done_i` completes one tile write-back, not the whole layer.

Current packed address format is NHWC-like:

```text
n_tiles    = ceil(n_size / COL)
global_row = tile_r * ROW + row_inside_tile
ao_addr    = out_base_addr + global_row * n_tiles + tile_c
```

Rows outside `m_size` in the last M tile are not written.

## Adding a New Layer Device

A new layer device should:

1. Implement its own internal controller and datapath.
2. Use `start_i`, `busy_o`, and `done_o` as layer-level control signals.
3. Use the switcher SRAM read interfaces for activation and weight reads.
4. Emit raw output tiles through the shared postprocess interface.
5. Use the shared `wb_buffer` and `wr_controller` interface for write-back.
6. Keep `done_o` low until all tiles, postprocess operations, and write-backs for the layer are complete.

The switcher only needs a new layer opcode decode when a new device type is
added. The postprocess and write-back protocol should remain unchanged.
